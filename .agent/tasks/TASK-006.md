## Objective

Add a vendor-neutral, provider-agnostic extraction layer that converts natural-language text into **candidate structured Constraints and Claims**.

The LLM is an extraction assistant only.

It must never:
- decide whether a constraint is authoritative;
- bypass Constraint / Claim model validation;
- mark a claim VERIFIED;
- fabricate execution evidence;
- mutate the ledger automatically without an explicit caller action;
- override provenance supplied by the caller.

The deterministic core remains authoritative:

```text
natural-language requirements
  -> extraction adapter
  -> validated candidate Constraint objects
  -> caller may add to ConstraintLedger
  -> SpecGuard remains authoritative

natural-language completion text
  -> extraction adapter
  -> validated atomic Claim objects
  -> EvidenceGate remains authoritative
  -> VERIFIED / CONTRADICTED / UNVERIFIED
```

## Package boundary

Implement under a neutral package such as:

```text
src/agentcontract/extraction/
```

Do not add OpenAI/Anthropic/Gemini SDK dependencies in this task.

At minimum implement provider-neutral equivalents of:

## StructuredExtractionClient

The client protocol should be small and vendor-neutral.

Equivalent shape is acceptable:

```python
class StructuredExtractionClient(Protocol):
    def extract(
        self,
        *,
        task: str,
        text: str,
        schema: Mapping[str, Any],
        context: Mapping[str, Any] | None = None,
    ) -> Mapping[str, Any]:
        ...
```

The exact API may differ, but:
- provider-specific SDK types must not leak into core extraction models;
- model output must be treated as untrusted structured data;
- the client must be invoked exactly once per extraction request unless the public API explicitly documents batch behavior;
- do not silently retry malformed output inside the core adapter.

## Requirement extraction

Implement an API equivalent to:

```python
result = RequirementExtractor(client).extract(
    text,
    source=ConstraintSource.USER,
    source_location="prompt:12",
    author="user",
)
```

### Authority rules

The caller, not the LLM, supplies:
- `ConstraintSource`;
- `source_location`;
- `author`;
- raw `source_text`.

The LLM may propose:
- name;
- description;
- strength;
- rule_effect;
- applicability scope;
- compliance scope when applicable.

But the adapter must enforce existing domain invariants.

Critical rules:
1. LLM output cannot change caller-supplied provenance source.
2. `ConstraintProvenance.source_text` must retain the original caller text, not rewritten model prose.
3. AGENT_INFERENCE must not become HARD.
4. REQUIRE/PREFER must contain a valid compliance_scope.
5. invalid enum values / malformed scopes fail validation; do not coerce arbitrary prose into a different valid rule.
6. extraction result preserves deterministic item order returned by the structured response.
7. IDs must be caller-supplied or generated by an injected deterministic ID factory; do not rely on free-form model-generated IDs as authoritative identity.
8. no extracted constraint is automatically inserted into ConstraintLedger.

## Claim extraction

Implement an API equivalent to:

```python
result = ClaimExtractor(client).extract(
    final_text,
    trace_id=runtime.trace_id,
    session_id=runtime.session_id,
)
```

The extractor converts completion text into **atomic typed claims**.

Examples:
- "pytest passed and build.bin exists" should be representable as two distinct claims;
- "the architecture is excellent" must become GENERIC or be omitted, never TOOL_SUCCEEDED;
- agent text itself is never evidence.

The LLM may propose:
- claim_type;
- description;
- call_id;
- tool_name;
- exact command;
- target_path;
- expected_exit_code.

The adapter/caller supplies authoritative trace/session scope.

Critical rules:
1. model output cannot override caller-supplied trace_id/session_id.
2. extracted claims remain unverified until EvidenceGate runs.
3. unknown/non-deterministic semantic statements become GENERIC or diagnostics; never force them into a verifiable type.
4. claim IDs come from an injected deterministic ID factory or explicit caller mapping, not trusted free-form model identity.
5. preserve output order.
6. duplicate claim IDs must be impossible through the adapter's own ID generation.
7. do not invent call_id/tool_name/command from trace data unless the caller explicitly supplies such context to the extraction request.
8. extraction must not inspect private chain-of-thought; only caller-provided observable text/context.

## Draft vs durable models

Prefer separating untrusted LLM output from durable domain models.

Recommended pipeline:

```text
raw mapping
  -> ConstraintDraft / ClaimDraft
  -> deterministic validation / normalization
  -> durable Constraint / Claim
```

Do not deserialize raw model output directly into a trusted Constraint with caller-authoritative provenance fields.

## Extraction results and diagnostics

Return a durable/inspectable result that includes at least:
- ordered extracted items;
- diagnostics/warnings for skipped or unsupported items;
- no hidden partial mutation.

Malformed whole-response behavior must be explicit:
- either raise an extraction validation error;
- or return a failed result with zero durable items and diagnostics.

Do not silently ignore malformed fields while still claiming full success.

## Prompts / schemas

If prompt templates are included:
- keep them small and provider-neutral;
- explicitly instruct structured output only;
- explicitly say not to infer execution evidence;
- explicitly say not to invent provenance authority;
- no model-specific prompt hacks in core.

Generate or expose JSON Schema from typed draft models where practical.

## Integration helper

Add a narrow optional helper to the runtime or extraction package for:

```python
claims = claim_extractor.extract(...).items
verification = runtime.verify_claims(claims)
```

Do not make extraction automatic inside `runtime.execute()`.

Do not auto-add extracted constraints to the ledger.

**Implementation summary:**  
- **Environment Baseline:** Developed and tested exclusively on the user's installed local **Python 3.12.9** baseline (`python --version` -> `Python 3.12.9`). Zero network calls, zero vendor SDK dependencies (no OpenAI, Anthropic, Gemini, or LangChain SDKs).
- **Package Architecture (`src/agentcontract/extraction/`):**
  - `StructuredExtractionClient` (`client.py`): Vendor-neutral `@runtime_checkable` protocol defining `extract(*, task, text, schema, context) -> Mapping[str, Any]`.
  - `ExtractionRequest` (`client.py`): Immutable typed request encapsulation for structured extraction.
  - `FakeStructuredExtractionClient` (`client.py`): In-memory deterministic fake client recording invocation count (`call_count`) and chronological request history (`requests`), supporting FIFO canned response queues or custom request-handling callables.
  - `ConstraintDraft`, `ConstraintScopeDraft` (`models.py`): Untrusted candidate requirement models.
    - `model_config = ConfigDict(frozen=True, extra="forbid")` prevents unknown or misspelled fields from being silently ignored.
    - No unsafe defaults: `strength`, `rule_effect`, and `scope` are required fields.
    - Scope items in `paths`, `tools`, `actions` must strictly be `str`; no `str(item)` coercion; non-string items (e.g. `int`, `bool`, nested object) or empty strings immediately raise `ExtractionValidationError`; `set` and `frozenset` continue to be rejected.
    - Empty or omitted applicability scopes are strictly rejected in v0.1 (`is_empty()` check), preventing extracted constraints from silently becoming global rules.
    - Explicitly declared spoof fields (`id`, `source`, `author`, `source_location`, `source_text`) allow audit diagnostics while durable `Constraint` preserves caller-owned values.
  - `ClaimDraft` (`models.py`): Untrusted candidate claim model.
    - `model_config = ConfigDict(frozen=True, extra="forbid")` ensures unexpected fields like `verdict="VERIFIED"` or `status="SUCCESS"` are strictly rejected or recorded as ERROR diagnostics.
    - Contains no verdict attribute; maps into durable `Claim` objects via `to_claim()`.
    - Explicitly declared untrusted fields (`claim_id`, `trace_id`, `session_id`) ensure caller-owned trace/session scope and ID cannot be spoofed.
  - `ExtractionDiagnostic`, `DiagnosticSeverity` (`models.py`): Structured diagnostic records (`ERROR`, `WARNING`, `INFO`) tracking issues, invalid fields, and authority/scope spoofing attempts.
  - `ExtractionResult[T]` (`models.py`): Immutable generic container aggregating extracted durable items, diagnostics, and raw response mapping, supporting iteration, indexing, length, and JSON round-trip serialization.
  - `RequirementExtractor` (`requirements.py`): Provider-neutral extractor converting natural language text into candidate `Constraint` models.
    - Client invoked exactly once per request.
    - Caller supplies authoritative `source: ConstraintSource` (required, no default `source=USER`).
    - Caller supplies `source_location`, `author`, and exact original `source_text`.
    - Invariant enforced: `AGENT_INFERENCE` cannot be declared with `HARD` strength.
    - Invariant enforced: `REQUIRE` and `PREFER` rules require an explicit non-empty `compliance_scope`.
    - Uses collision-resistant ID generator by default (`IdGenerator(deterministic=False)`); supports explicit injection of deterministic generators.
    - Full provenance spoof diagnostics emitted (`id`, `source`, `author`, `source_location`, `source_text`) with `AUTHORITY_SPOOF_IGNORED` code without affecting durable outputs.
    - Never mutates `ConstraintLedger` automatically.
  - `ClaimExtractor` (`claims.py`): Provider-neutral extractor converting natural language completion text into atomic `Claim` models.
    - Client invoked exactly once per request.
    - Caller supplies authoritative `trace_id` and `session_id`; model cannot spoof or redirect claim scope.
    - Decomposes sentences into distinct atomic claims (e.g. "pytest passed and build.bin exists" -> `TESTS_PASSED` + `FILE_EXISTS`).
    - Subjective or non-verifiable statements remain `GENERIC`.
    - Model claims like "tests passed" produce at most a `TESTS_PASSED` claim, remaining `UNVERIFIED` until EvidenceGate evaluates verifiable trace evidence. An `AGENT_MESSAGE` trace event alone never verifies it.
    - Uses collision-resistant ID generator by default (`IdGenerator(deterministic=False)`); supports explicit injection of deterministic generators.
    - Full scope and identity spoof diagnostics emitted (`claim_id`, `trace_id`, `session_id`) with `SCOPE_SPOOF_IGNORED` code.
  - `extract_and_verify_claims` (`helpers.py`): Narrow optional integration helper extracting completion claims with runtime trace scope and verifying them with `runtime.verify_claims()`.
  - `get_requirement_extraction_schema()`, `get_claim_extraction_schema()` (`models.py`): Standard JSON Schema specifications with `"additionalProperties": False` and strict required lists.
  - Top-level re-exports: All extraction primitives exported from `agentcontract.extraction` and root `agentcontract`.
